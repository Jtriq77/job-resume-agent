# 课程报告提纲（3000–5000 字）

> 这是写作提纲和素材索引，不是最终报告正文。

## 1. 问题与需求

- 应届生简历信息散、方向不确定、岗位筛选成本高；
- 目标用户与使用场景；
- 成功标准：四段完整、方向可选、一页可投、岗位可追踪；
- 当前证据：真实自用场景 + 设计文档；待补 3–5 位同学访谈与耗时记录。

## 2. 系统设计

- 五个页面：对话采集、表单填写、三档岗位、简历模板、投递追踪；
- 数据流：一段话 → 四段信息 → 方向 → 段落简历 → DOCX；
- 每页右侧处理记录：步骤、状态、说明；
- 失败处理：规则兜底、空四段兜底、旧简历失效、链接兜底。

## 3. 机器学习

- 分类：TF-IDF + NB，3,120/780，Macro-F1 0.7602；
- 聚类：TF-IDF + K-Means++，k=13，轮廓系数 0.0656；
- 排序：7 维特征 + LR，NDCG@5 0.8543 vs 基线 0.5839；
- 标签泄漏与弱标注的局限；
- 详见 `docs/ML_MODULES.md`、`docs/RESULTS.md`。

## 4. Agent 与 Skills

- 两个自建 Skill 的输入/输出/铁律；
- 运行时读取 `prompt.md`，不是文档摆设；
- 外部候选只做选型分析，未直接复用代码；
- 详见 `skills/README.md`。

## 5. 实验

- 分类指标、逐类 F1、消融；
- 聚类 k 试验、轮廓系数、纯度；
- 排序 NDCG/Recall 与基线；
- 待补：300 条人工金标准、100–150 对人工相关性、简历事实错误率/ATS/人工偏好。

## 6. 讨论与局限

- 银标准/弱标注不能外推；
- 免费云文件系统不持久；
- 模板只保留 21 个代表；
- 不自动提交，人工确认。

## 7. 复现与部署

- `requirements.txt`、`scripts/train_all_ml.sh`；
- Streamlit Cloud + Netlify，见 `DEPLOY.md`。

至少 5 条：job_radar、Streamlit、python-docx、TF-IDF/NB、K-Means、NDCG、Skills 参考等。
